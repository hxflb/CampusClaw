## Why

第 4 课已经能按班级检索并标出出处，但学生还不能对着题目连续追问。检索结果、教师写的提示词和技能没有进同一次回答。本变更把知识库接到解题助手里：教师规定助手是谁、是否启用解题引导；学生在同一会话里追问，回答以 SSE 逐段返回并留下出处。

课件：[第 5 课 · 提示词、AI 技能与流式会话](https://devops.hello1023.com/%E8%AF%BE%E4%BB%B6/%E7%AC%AC5%E8%AF%BE-%E8%AF%BE%E4%BB%B6-%E6%8F%90%E7%A4%BA%E8%AF%8DAI%E6%8A%80%E8%83%BD%E4%B8%8E%E6%B5%81%E5%BC%8F%E4%BC%9A%E8%AF%9D/index.html)。

## What Changes

- 每个班一份由教师保存的提示词，只描述助手角色；从下一轮提问生效。学生不能改。
- 本课只实现技能「解题引导」。开启时给思路，并引用本班材料的标题和位置，不直接给最终答案。关闭后同一问题的回答方式明显不同。学生不能开关。
- 选定技能之后再按会话班级做混合检索。命中则在同一次回答里标出处；没有命中时链路不中断：仍按角色与技能调用对话网关作答，引用列表下发空数组，正文剥掉 `[n]` 编号，也不写成整段的「资料中未找到」。
- 回答按会话保存在服务端。学生可连续追问。生成内容以 SSE 逐段返回。
- 不新增独立检索页。`POST /api/search` 与 `POST /api/ask` 仍保留，供第 4 课契约使用。

## Capabilities

### New Capabilities

- `tutor-session`：班级提示词、解题引导开关、会话持久化、检索后的流式回答，以及学生不能改提示词或技能。

### Modified Capabilities

- 无。第 4 课检索与非流式 `POST /api/ask` 的要求保持不变。

## Impact

- api：提示词、技能、会话与 SSE 消息接口；生成时组装提示词、技能规程和检索片段。
- MySQL：`class_prompts`、`class_skills`、`conversations`、`conversation_messages`。
- web：解题助手页；Nginx 对 `/api/` 关闭代理缓冲，避免 SSE 被攒包。
- 密钥仍只在 api 容器，不下发浏览器。

## Non-goals

- 不做作业提交、作业批改、错题讲解、关怀式对话、异步队列。
- 不实现解题引导以外的技能。
- 不把提示词写成某一类题目的解题步骤；步骤只放在技能规程里。
- 不新增独立检索页，不做交叉编码器重排，不把 Qdrant 或模型网关暴露给浏览器。
