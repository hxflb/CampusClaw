## Purpose

学生就题目连续追问时，同一次回答必须用上教师已保存的角色提示词、解题引导技能的当前开关，以及本班知识库检索结果；回答按会话保存，并以 SSE 逐段返回。

## ADDED Requirements

### Requirement: 教师保存角色提示词

系统 MUST 为每个班保存一份提示词，预置内容只描述助手角色，MUST NOT 把某一类题目的解题步骤写进预置提示词。教师 MUST 能覆盖本班提示词。学生 PUT MUST 返回 403。请求中的 `class_id` MUST 丢弃，写入班级只来自登录会话。空白提示词 MUST 返回 400。已生成的助手消息 MUST NOT 因之后的保存被改写；下一次提问 MUST 使用新提示词。

#### Scenario: 学生不能修改提示词

- **WHEN** 学生调用 `PUT /api/prompt`
- **THEN** HTTP 403
- **AND** 该班已保存的提示词保持不变

#### Scenario: 伪造班级不能改到他班

- **WHEN** A 班教师保存提示词，且 JSON 中携带 B 班 `class_id`
- **THEN** 只有 A 班提示词变化
- **AND** B 班提示词保持不变

#### Scenario: 下一轮才生效

- **WHEN** 某会话已有一条助手回答，之后教师修改提示词
- **THEN** 该条已保存回答的正文保持不变
- **AND** 同一会话的下一次提问所加载的提示词摘要与修改后的正文一致

### Requirement: 解题引导由教师开关

系统 MUST 提供且仅提供技能 `guide`（解题引导），默认开启。教师 MUST 能开关本班该技能。学生 PUT MUST 返回 403。其他技能 key MUST 返回 404。技能规程 MUST 由服务端附加，MUST NOT 要求教师把规程写进提示词。

开启时，有依据的回答 MUST 给出思路，并引用本班材料的标题和位置，MUST NOT 直接给出最终答案。关闭后，同一问题的回答方式 MUST 明显不同，并且可以直接作答。两种情况下，有命中时系统消息 MUST 都包含已保存提示词原文；仅开启时系统消息 MUST 包含「不要直接给出最终答案」。

#### Scenario: 学生不能开关技能

- **WHEN** 学生调用 `PUT /api/skills/guide`
- **THEN** HTTP 403
- **AND** 该班技能开关保持不变

#### Scenario: 开启时不直接给最终答案

- **WHEN** 解题引导开启，且本班检索有命中，对话网关未配置
- **THEN** 回答正文包含材料标题与切片位置
- **AND** 回答正文不复述切片中的结论句

#### Scenario: 关闭后回答方式不同

- **WHEN** 同一问题在解题引导关闭后再次提问，且对话网关未配置
- **THEN** 回答正文与开启时不同
- **AND** 关闭时的回答可以直接写出依据中的结论

#### Scenario: 不实现其他技能

- **WHEN** 教师调用 `PUT /api/skills/care`
- **THEN** HTTP 404

### Requirement: 检索之后才生成，无依据不编造

每一轮 MUST 先读取提示词和技能，再按会话班级做 hybrid 检索并最多取 4 条。请求中的 `class_id` 与 `system` MUST 丢弃。无命中时正文 MUST 为「资料中未找到相关内容」，citations MUST 为空，MUST NOT 调用对话网关，MUST NOT 沿用上一轮出处。有命中时 citations MUST 含材料标题、切片序号和字符区间，且 MUST 来自本班。

#### Scenario: 无关问题不调用生成

- **WHEN** 用户询问本班材料不可能出现的内容（如天气）
- **THEN** 回答为固定未找到文案，citations 为空
- **AND** 对话网关没有收到请求

#### Scenario: 跨班词不能带出他班材料

- **WHEN** A 班用户提问，JSON 携带 B 班 `class_id`，问题只在 B 班材料中出现
- **THEN** 回答不得引用 B 班材料标题

### Requirement: 会话持久化与 SSE

系统 MUST 把用户问题和助手回答按会话保存，且会话只属于创建者。他人访问该会话 MUST 返回 404。连续追问 MUST 使用同一会话在服务端保存的历史，而不是客户端提交的 `messages`。`POST /api/conversations/{id}/messages` MUST 以 `text/event-stream` 返回，并且至少包含 `meta`、`delta` 与 `done`。`meta` MUST 标明是否用了已保存提示词、解题引导是否开启，以及本轮命中条数。

#### Scenario: 追问仍在同一会话

- **WHEN** 学生在已有会话中第二次提问
- **THEN** 该会话消息条数增加
- **AND** 重新读取会话时仍能看到前一轮问答

#### Scenario: 他人不能读取会话

- **WHEN** 另一名已登录用户读取该会话
- **THEN** HTTP 404

#### Scenario: 创建者可以删除自己的会话

- **WHEN** 创建者调用 `DELETE /api/conversations/{id}`
- **THEN** 该会话及其消息被删除
- **AND** 再次读取返回 404

#### Scenario: 他人不能删除会话

- **WHEN** 另一名已登录用户删除该会话
- **THEN** HTTP 404
- **AND** 原创建者仍能读取该会话

### Requirement: 解题助手页显示技能状态并按条删除

学生打开解题助手时 MUST 看到解题引导当前是开启还是关闭，且 MUST NOT 提供修改入口。会话列表展开后，每一项 MUST 带有只针对该会话的删除。删除 MUST 只作用于创建者自己的该条会话。

#### Scenario: 学生看到开关状态

- **WHEN** 学生打开解题助手，且本班解题引导为开启
- **THEN** 页面显示解题引导已开启
- **AND** 页面没有保存提示词或切换技能的控件

#### Scenario: 按条删除会话

- **WHEN** 创建者在会话列表中删除其中一项
- **THEN** 只有该项及其消息被删除
- **AND** 其余会话仍可打开

#### Scenario: 回答逐段推送

- **WHEN** 学生提交非空问题
- **THEN** 响应类型为 `text/event-stream`
- **AND** 事件中有 `delta` 与 `done`
- **AND** `done` 之前回答已写入该会话

### Requirement: 回答中的参考资料只显示标题

解题助手列出的参考资料 MUST 只显示资料标题，并且 MUST 与该回答正文处在同一个框内。MUST NOT 在该列表中展示切片摘录、切片序号或字符区间。

#### Scenario: 有命中时标题在回答框内

- **WHEN** 一轮回答命中了本班资料
- **THEN** 参考资料标题出现在该回答正文所在的框内
- **AND** 页面不展示该资料的摘录正文

### Requirement: 会话锁定智能体并生成标题

新建会话 MUST 指定本班已启用的智能体，并把编号写入会话。不存在、他班或未启用 MUST 返回 404。本班没有已启用智能体时 MUST 返回 400。会话还没有任何消息时，创建者 MUST 能把它改成另一个本班已启用智能体；这次修改 MUST 只更新当前会话，MUST NOT 新建会话。不存在、他班或未启用 MUST 返回 404。会话已有消息后 MUST NOT 再更换，再次修改 MUST 返回 409。提问请求里的智能体编号 MUST 丢弃，回答 MUST 使用会话上记下的智能体。该智能体后来被停用时，已有会话 MUST 仍可提问。新建时标题 MUST 为「新的提问」。首轮提问后 MUST 改为该提问的前 24 字；截取为空则保留占位串。之后的提问 MUST 只刷新 `updated_at`，会话列表 MUST 按它倒序。助手消息 MUST 记下本轮命中的技能名；没有命中技能时该字段为空。

#### Scenario: 建会话时选定智能体

- **WHEN** 学生用本班一个已启用智能体新建会话
- **THEN** 会话记下该智能体，标题为「新的提问」

#### Scenario: 未开始时只更换当前会话的智能体

- **WHEN** 创建者把一条还没有消息的会话改成另一个本班已启用智能体
- **THEN** 会话编号不变，并记下新的智能体
- **AND** 会话列表不增加新会话

#### Scenario: 已有消息时拒绝更换

- **WHEN** 创建者对一条已有消息的会话更换智能体
- **THEN** HTTP 409
- **AND** 会话仍使用原来的智能体

#### Scenario: 之后不能更换智能体

- **WHEN** 同一会话的后续提问带上另一个智能体编号
- **THEN** 回答仍使用会话上记下的智能体

### Requirement: 上下文只取末尾六条

送进模型的历史 MUST 是该会话按写入顺序的末尾 6 条消息。角色不是 user 或 assistant 的记录，以及正文为空的记录，MUST 跳过。每条历史正文 MUST 截断到 500 字。本轮提问 MUST 在生成前写入，因此落在这个窗口内；交给模型的本轮用户消息改带检索资料，每条资料截断到 800 字。

#### Scenario: 更早的消息不进上下文

- **WHEN** 一个会话里已有超过 6 条非空的 user 或 assistant 消息
- **THEN** 模型只收到其中末尾 6 条所对应的上下文
