## Context

主应用仍是一个 CampusClaw。MCP 服务与 API 在同一 Compose 网络，不另开仓库，也不把端口映射到宿主机。本变更按第 6 课「模型声明—宿主执行」的调用循环实现，替换早先「路由命中就直接预调用一次」的写法。

## Decisions

### D1 自建 MCP

`mcp-demo` 监听容器内 8090。`GET /health` 不鉴权。`POST /mcp` 实现 JSON-RPC 2.0 的 `initialize`、`tools/list`、`tools/call`。令牌读环境变量 `MCP_AUTH_TOKEN`。无令牌或令牌错误返回 401。非法请求返回带 message 的 JSON-RPC 错误。工具为 `formula_hint`、`unit_convert` 和 `weather_query`，名称以小写字母开头且不含连字符。每个工具带 `inputSchema`，宿主的参数校验就用这一份结构。工具只给提示、不给最终答案。

### D2 登记与发现

教师提交名称、Base URL 与可选令牌。令牌只写不读：入库、只供发请求时使用，任何接口响应都不含原文，只回一个 `has_token` 布尔；未填时回退到服务端的 `MCP_AUTH_TOKEN`。连接＝`initialize` 握手 + `tools/list` 发现，成功后用本次清单整体替换旧清单并标记已连接；握手或发现任一步失败则停在未连接，返回可读原因。断开把服务器标记为未连接，对外清单清空。发现结果（名称、说明、输入结构）保留为最近一次快照，用于重建工具声明与判定「被拒」，但未连接时不出现在接口返回里。学生访问这些接口返回 403。其他班的服务器编号返回 404，与不存在的编号完全一致。

### D3 工具声明、调用循环与上限

候选集只来自本次选中的技能：技能写了 `工具名@服务器名` 才有工具，`knowledge_search` 不是模型可调用的工具。声明三项（名称、说明、输入结构）都取自发现结果，不由人手写。

一轮提问内：宿主把声明随消息发给对话网关；模型回结构化 `tool_calls`（工具名 + 参数对象）；宿主按该工具的 `inputSchema` 校验参数，通过后带令牌执行；成功、工具报错、宿主拒绝都以工具消息角色回传，模型据此再决定。循环终止条件：模型不再请求工具、轮次达到 `MCP_MAX_ROUNDS`、或本会话本轮累计调用达到 `MCP_MAX_CALLS`。超限是优雅降级——不再提供工具声明，让模型用已有信息作答，而不是把整轮变成 503。

工具失败不中断对话：检索与生成照常。工具返回属于不可信数据，进上下文前先扫指令式句式，命中就整条丢弃并换一句固定说明。

### D4 事件与审计

`meta` 仍只带状态、技能与引用列表（第 5 课的四类事件不变）。每次执行完一轮调用，先推一次 `tool_calls` 事件（`round` + `calls[].{ref,status,text}`）再推该轮正文，因此调用事件一定早于第一个正文分片；本次没有任何调用时不推该事件。

审计一行回答五个问题：工具引用、状态（ok/error/denied）、用户、会话与轮次、时间。服务器已不存在时这次失败无法归属，不写记录；服务器存在但未连接时写 `denied`。教师按本班查看。

### D5 界面

管理页显示服务器、`has_token`、连接状态、已发现工具的名称与完整说明、最近调用记录。对话页在正文出现前显示本次用到的工具及其状态。
